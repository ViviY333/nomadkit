## App 隐私建议答案（以最终行为再次核对）

- 精确位置：用于 App 功能；不与用户身份关联；不用于追踪
- 粗略位置：如果 Apple 的问卷按定位能力要求申报，则同样选择用于 App 功能
- 照片或视频：App 使用系统照片选择器；若不上传或保存照片内容，通常无需申报“照片或视频”采集
- 其他用户内容：本地保存的个人资料、清单和足迹如果不发送到开发者服务器，通常不属于开发者“收集”的数据
- 标识符、使用数据、诊断：仅当最终构建中的 SDK 或服务实际收集时申报

> App Store 的“收集”通常指数据离开设备并可由开发者或第三方在一定时间后访问。最终答案必须根据构建中所有 SDK、接口和隐私政策逐项确认。

## 提交前阻塞项

1. 工程当前 `MARKETING_VERSION` 仍为 `0.2.0`，需要改为计划提交的 `2.0`。
2. 工程当前 `CURRENT_PROJECT_VERSION` 为 `1`。新构建号必须高于已上传构建，建议本次使用 `200` 或团队连续编号。
3. 当前线上 1.0 支持 iPhone 和 iPad，但本地 App target 的 `TARGETED_DEVICE_FAMILY` 是仅 iPhone (`1`)。更新版通常不能移除上一版本已支持的设备系列；归档前需要恢复 iPad 支持并完整适配，或先在 App Store Connect/Xcode 验证 Apple 是否允许该兼容性变化。
4. 工程未发现 `PrivacyInfo.xcprivacy`。需要根据实际使用的 API 和第三方 SDK 添加并核对隐私清单。
5. `NomadKit-Info.plist` 未发现 `ITSAppUsesNonExemptEncryption`。如果只使用 Apple 系统提供的标准加密/HTTPS且符合豁免，建议声明为 `NO`，并按实际情况回答出口合规问题。
6. 设置页中的“Privacy policy”“Terms and conditions”以及部分开关看起来仍是静态界面；提交前必须确保按钮可用，或移除尚未完成的入口，避免触发 App Completeness 拒审。
7. 确认 `Sign in` 不再是无响应的占位入口；如果 2.0 不提供登录，应移除或隐藏。
8. 用 Release 构建确认不会携带开发参数 `-onboarding-reset`，并在真机测试无网络、拒绝定位、拒绝照片权限等路径。
